Dot imagery foundry

Every subject is a procedural 3D scene, rendered offscreen, reduced to a luminance field, then pushed through one halftone screen. Nothing is photographed, licensed or generated, so all of it is owned and can be re-rendered at any size or angle.

This page is the tuning rig and the library viewer. Production runs through scripts/render_dot.py, which uses the same engine with the sliders locked.

Roles

Role decides output size and dot pitch together. Pitch is set so a hero and a figure show the same perceived dot size once each is displayed at its intended width, which is why the numbers are not proportional.

Library

Previewed at card scale. Use the export button for a one-off, or the CLI for anything going into a brief.

These sliders are for deciding the constants, not for producing assets. Whatever you leave them on does not affect the CLI.

Rules for using it

  1. One image per brief at the top, and at most one more inside it. The device stops working the moment it is everywhere. If a brief seems to want three, two of them are decoration.
  2. Never where a real chart belongs. These are subject imagery, not evidence. A dot rendering of a port signals that the brief concerns ports. It never substitutes for a figure and it never carries a number.
  3. Never captioned as data. The caption names the subject and says rendered, so no reader can mistake a procedural scene for a photograph of a specific real facility.
  4. Same engine, always. A one-off tuning is how a system becomes a folder.
  5. Published work keeps the look it shipped with. If a constant changes, bump the engine version. Do not re-render briefs that are already out; a dated brief is a document of record.
